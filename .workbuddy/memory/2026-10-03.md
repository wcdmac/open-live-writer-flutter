## 评估：封面图块增加本地图片（用户问"只支持图片链接"）

核查结论：**本地图片上传其实已基本具备**，用户感知"只支持链接"源于插入入口与可发现性。
- 聚焦态封面字段 `_CoverImageField._pickAndUpload`（`cover_image_field.dart:48`）已接 `uploadMedia`，有设备选择按钮（`cover_image_field.dart:111`），上传走 `svc.uploadMedia`（REST/XML-RPC 均支持），返回 URL 写入 `<img src>`，`parseCover/buildCoverHtml`（`block_document.dart:709-740`）往返无损。
- `uploadMedia` 链路：`post_editor_page.dart:1006` → `block_editor.dart:117`(_BlockCard) → `block_card.dart:148`(_CoverImageField)，全程非空。
- **真正缺口**：插入条 `_insertCover`（`insert_bar.dart:323`）只弹 URL 输入框，不像 `_insertImage`/`_insertVideo` 提供「设备/链接」底部菜单；且字段内设备按钮只是 URL 框的小后缀图标，可发现性低。
- 推荐最小方案：让 `_insertCover` 镜像 `_insertImage`（设备/链接 bottom sheet + 上传 + 插入带 URL 的 cover 块），纯增量、复用 `normalizeImageUpload`/`uploadMedia`/既有 l10n（pickFromDevice/enterImageUrl），低风险。语义上"本地图片"= 选设备→传到博客媒体库→嵌托管 URL（同图片块），非 data-URI 内嵌（WP 发布需托管 URL）。
- 已实施（用户确认"两者都做"）：提交 `475e2d1`，`tmp/cover-local-image` 分支 CI(Analyze+Test) 全绿后 `--ff-only` 合入 `main`，临时分支已删。方案 A=`_insertCover` 加设备/链接菜单；方案 B=cover 字段 URL 框下显示醒目"从设备选择"按钮、后缀仅留 spinner。无新 l10n、无序列化改动。
